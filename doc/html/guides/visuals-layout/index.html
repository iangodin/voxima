    Visuals and layout¶

    The code on this page is from the layout example (examples/layout), which is built with Voxima.

    Shapes¶

    auto circle = std::make_unique<Circle>( 0.7F, theme.palette().blue );   // radius, color
auto &dot = stage.visuals.add( std::move( circle ) );
dot.position = { -3.F, 0.F };

auto &box = stage.visuals.add( std::make_unique<Rectangle>( 1.F, 0.5F, theme.palette().green ) );  // half width, half height

    Every visual has the same properties:

    Property Meaning
    position Where its origin is, in its parent's frame (stage units, y up)
    rotation, scale_x, scale_y Turned and scaled about its origin
    color Fill color (alpha makes it see-through)
    fill_gradient A fill that changes color across it, instead (see Gradients)
    stroke_thickness, stroke_color, stroke_dash Its outline (see Dashed lines)
    tags Names for finding it again (see Tags)

    Line has a start and end; a Path is made of MoveTo and CubicTo commands; Group holds other visuals. A group's position, rotation, scale and color multiply down into its children, so fading a group fades everything in it.

    Groups¶

    auto &row = stage.visuals.add( std::make_unique<Group>() );
row.add( std::make_unique<Circle>( 0.4F ) );
row.add( std::make_unique<Circle>( 0.4F ) );

    Iterate a group with a range-for; size(), clear(), remove( &child ) (hands the child back) and replace( &old, new ) work on its direct children.

    Drawing order¶

    A group draws its children in order, so what comes later is in front. To put something elsewhere in that order, use insert( index, visual ) (0 is the back) instead of add, or move a child that is already there:

    stage.visuals.to_front( &back );                                            // now the rectangle hides the circle
auto &behind = stage.visuals.insert( 0, std::make_unique<Circle>( 2.F, palette.green ) ); // behind them both

    to_front, to_back, raise and lower take a direct child, and return false if it is not one. All of these stay in front of the stage's background.

    Dashed lines¶

    Any stroke can be dashed or dotted, with a StrokeDash:

    auto &line = stage.visuals.add( std::make_unique<Line>() );
line.stroke_color = palette.blue;
line.start = { -5.F, 2.F };
line.end = { 5.F, 2.F };
line.stroke_thickness = 0.06F;
line.stroke_dash = StrokeDash::dashed( 0.4F, 0.2F ); // 0.4 on, 0.2 off

auto &ring = stage.visuals.add( std::make_unique<Circle>( 1.2F, Color{ 1.F, 1.F, 1.F, 0.F } ) );
ring.stroke_color = palette.orange;
ring.stroke_thickness = 0.12F;
ring.stroke_dash = StrokeDash::dotted( 0.3F );       // round dots, 0.3 apart

co_await tween( stage, 3s, ease_linear, [&]( float t ) { ring.stroke_dash.offset = -3.F * t; } ); // they march

    A pattern is lengths on and off in turn, in the visual's own units, so it scales with the visual just as its stroke does (and stretches with it under an uneven scale). offset starts it further along; tween it for dashes that march. Each piece of a path (each MoveTo) starts the pattern again. A pattern under half a pixel is drawn as a whole line.

    ConnectorOptions::dash dashes a connector's line and not its arrow heads, and GraphOptions::dash a graph's curve. Dashes stay as they are in draw_on, and a morph blends them: between two patterns, or with the gaps opening from a whole line. The exception is a line that becomes a filled shape: it is drawn as a whole line on the way, so the gaps close as soon as it starts.

    Gradients¶

    Any shape can be filled with a linear or radial gradient instead of a plain color:

    auto &bar = stage.visuals.add( std::make_unique<Rectangle>( 1.F, 2.F ) );
bar.fill_gradient = Gradient::across( box_of( bar ), 90.F, { { 0.F, Color::hex( 0x101010 ) }, { 1.F, Color::hex( 0xF0F0F0 ) } } );

auto &disc = stage.visuals.add( std::make_unique<Circle>( 2.F ) );
disc.fill_gradient = Gradient::radial( { 0.F, 0.F }, 2.F, { 0.7F, 0.7F }, { { 0.F, palette.yellow }, { 1.F, palette.red } } );

auto &title = stage.visuals.add( make_text( theme, "Gradients", FontStyle{ Intent::TITLE } ) );
fill_each_with_gradient( title, 90.F, { { 0.F, palette.blue }, { 1.F, palette.pink } } ); // a gradient per glyph

    A gradient is placed in the visual's own coordinates, so it moves, turns and scales with the visual. Gradient::across fits a linear one to a box at an angle (0 goes to the right, 90 up); box_of gives that box only while the visual is still at its origin, so use it before placing the visual. Stops are at offsets from 0 to 1. The visual's color tints the gradient and its alpha fades it, and white in a stop is the theme's text color, as everywhere.

    Text has a gradient per glyph, not one across a word: fill_each_with_gradient gives each shape below a visual its own, across that shape.

    Colors blend as they are written, in sRGB and not in linear light; add stops to follow any other curve. A frame has 8 bits a channel and gradients are not dithered, so a long, dark ramp shows bands (from 0 to 16 across 1600 pixels: 17 bands, each about 94 pixels wide). Between stops with different alpha, Voxima's renderer blends colors premultiplied, so a color fading out does not pick up the hue of the transparent stop, as it would in a browser looking at the same SVG. A gradient that goes nowhere (its ends the same, or a radius of 0) is drawn in its last color.

    A morph blends gradients: a plain fill and a gradient turn into one another, and two of a kind blend their stops and their places. A linear and a radial one cannot become one another, so they pass through a plain color, the average of the two:

    auto square = std::make_unique<Rectangle>( 2.F, 2.F );
square->position = { 4.F, -0.5F };
square->fill_gradient = Gradient::across( AABB{ { -2.F, -2.F }, { 2.F, 2.F } }, 0.F, { { 0.F, palette.green }, { 1.F, palette.blue } } );
co_await morph( stage, disc, std::move( square ), 2s, ease_cubic_in_out ); // a radial one and a linear one pass through a plain color

    Placing things against each other¶

    Hard-coded coordinates are fine for a couple of things. For anything more, place visuals relative to each other (visuals/Placement.h), so a change in size or text does not make things overlap. The boxes used are the ones layout uses: for text, the advance widths and line height, not just the ink.

    move_to( title, { 0.F, 3.5F }, Anchor::TOP );          // its top edge at y = 3.5
next_to( label, dot, Anchor::BOTTOM );                 // under it, a gap between
next_to( panel, other, Anchor::RIGHT, 1.0F );          // to its right, 1 unit apart

    Anchor is CENTER, LEFT, RIGHT, TOP, BOTTOM or a corner (TOP_LEFT, ...). Visuals placed against each other must be in the same group (or both directly on the stage).

    Rows, columns and grids arrange the children of a group:

    arrange_row( group, { .gap = 0.5F } );                     // left to right, centered on the origin
arrange_column( group, { .gap = 0.3F, .align = Align::START } );
arrange_grid( group, 3, { .column_gap = 0.4F, .row_gap = 0.2F } );   // rows of 3
distribute_row( group );                                   // equal spaces between, outer two stay put
align_edges( group, Anchor::LEFT );                        // line up on an edge

    Align (across the direction of the row) is START, CENTER, END, or BASELINE, which lines up the baselines of text of any size.

    Keeping things on screen:

    keep_inside( group, safe_area( stage.camera ) );   // moved the least it takes
fit_inside( group, safe_area( stage.camera ) );    // and scaled down if it is too big

    safe_area is the picture's frame, at zoom 1, pulled in by a margin (0.5 units by default).

    box_of( visual ) and point_at( visual, anchor ) give a visual's box and one of its points, in its parent's frame, for your own placement.

    Panels, lists and tables¶

    A panel is a rounded box fitted round something:

    auto &panel = stage.visuals.add( make_panel( make_text( theme, "Theorem", style ), { .padding = 0.5F } ) );

    PanelOptions sets the padding, corner radius, fill, outline and outline_width, and an optional shadow. The default fill and outline are faint tints of the text color, so a panel suits any palette.

    A list is a bulleted or numbered column:

    auto &list = stage.visuals.add( make_list( theme, { "first", "second", "third" }, { .numbered = true } ) );
list.row( 1 );    // each row is a visual of its own, to show or light on its own

    Long items wrap if you set max_width; every row is spaced evenly.

    A table has rows of cells, a header, and optional rules, stripes and wrapping:

    const std::vector<std::vector<std::string>> rows = {
    { "Name", "Scale", "Use" },
    { "tiny", "0.5", "footnotes" },
    { "huge", "2.0", "titles" } };
auto &table = stage.visuals.add( make_table( theme, rows, { .striped = true, .max_width = 10.F } ) );
table.cell( 1, 2 );   // a cell is a visual

    Cells can also be visuals (a formula, a picture); then give make_table a vector of rows of std::unique_ptr<Visual>.

    Pictures¶

    An Image shows a picture file: set its path, half_width and half_height. A picture is not an outline, so it morphs only into the same picture (moving to where that is); otherwise it cross-fades.

    Tags¶

    Tag a visual to find it again after it is built into something bigger:

    tag_visual( dot, "hero" );
Visual *found = find_tag( stage.visuals, "hero" );

    A path of names looks inside each match in turn (find_tag( built, "fraction1", "bar" )). Math formulas and other composites name their own parts too (numerator, denominator, bar, ...), listed in visuals/Tags.h. Tags are also what morphing uses to follow a part from one visual to the next.
